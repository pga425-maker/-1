# 모의투자 리그 — 축제 부스용 모의 주식 수익률 대결

학교 축제 부스에서 참가자 최대 50명이 휴대폰으로 접속해 30분 동안 겨루는 웹앱이다.
실존 기업이 아닌 가상 종목과 가상 시장을 쓰고, 인터넷 없이 노트북 한 대에서 완전히 돌아간다.

한 판은 30분, 375틱, 틱당 4.8초다. 틱 길이 4.8초는 주식을 처음 해 보는 참가자가
상황을 판단하고 매매할 시간을 확보하기 위해 의도적으로 느리게 잡은 값이다.

## 무엇이 다른가

1. **참가자 주문이 저항으로 작용한다.** 가격은 관리자 시나리오대로 흐르되, 매수가
   몰리면 그 틱의 변동폭이 깎인다. 방향은 절대 뒤집히지 않는다.
2. **뉴스는 뜨고 나서 시간이 지나야 반영된다.** 헤드라인과 가격 반영 사이에 지연이
   있고, 화면에는 반영 대기 → 반영중 → 반영 완료 3단계 배지가 표시된다.
3. **수익률만 보지 않는다.** 위험조정 수익률, 매수 근거, 투자 성향까지 평가한다.
   자기가 고른 근거와 실제 매매 패턴이 다르면 그 괴리를 결과 화면에서 짚어 준다.

참가자에게 공매도 기능은 주지 않는다. 공매도는 뉴스 이벤트의 한 유형(펌프-덤프)으로만
등장하며, 순효과는 반드시 손실이 되도록 불변 조건으로 강제한다.

---

## 설치

인터넷이 되는 곳에서 미리 한 번 돌려 둔다. 행사장에서는 네트워크가 없어도 된다.

```bash
./setup.sh
```

하는 일: 파이썬 버전 확인 → 파이썬 패키지 설치 → 프론트 의존성 설치와 빌드 →
폰트 번들이 외부 주소를 참조하지 않는지 검사 → `.env` 생성.

필요한 것: Python 3.11 이상, Node.js 18 이상.

`.env` 의 `ADMIN_PASSWORD` 를 반드시 바꾼다.

## 실행

```bash
./run.sh
```

FastAPI 한 프로세스가 API, WebSocket, 프론트 빌드 결과를 전부 같은 포트로 서빙한다.
포트가 하나라서 QR 주소가 갈리지 않는다.

실행하면 접속 주소가 출력된다.

| 화면 | 주소 | 쓰는 사람 |
|---|---|---|
| 참가자 | `http://<노트북IP>:8000/onboard` | 휴대폰 QR |
| 프로젝터 | `http://localhost:8000/board` | 대형 화면 |
| 관리자 | `http://localhost:8000/admin` | 운영자 |

## 행사 당일 운영 순서

### 전날 또는 당일 아침

1. **네트워크 확인이 제일 중요하다.** 학교 와이파이에 단말 간 통신 차단
   (AP isolation)이 걸려 있으면 휴대폰이 노트북에 접속할 수 없다. 코드로 해결할 수
   없는 문제다. 반드시 휴대폰 한 대로 미리 접속해 본다.
   - 접속이 안 되면 노트북 핫스팟을 켜고 거기에 참가자를 붙인다.
   - 핫스팟은 동시 접속 인원 제한이 있으니 미리 확인한다.
2. `./setup.sh` 를 돌려 빌드가 최신인지 확인한다.
3. `./run_all_tests.sh` 로 전체 테스트를 돌린다. 결과는 `test_report.md` 에 남는다.
4. 노트북 절전과 화면 꺼짐을 끈다. 30분 동안 깨어 있어야 한다.

### 리허설 (본 라운드 전에 반드시 한 번)

```bash
./scripts/run_rehearsal.sh 50
```

봇 50명이 실제 서버에 HTTP 와 WebSocket 으로 붙어 한 판을 완주한다.
서버, DB, WebSocket, 체결 로직이 전부 돈다. 결과는 `rehearsal_report.md` 에 쌓인다.

보고서에서 확인할 것

- 예외와 타임아웃이 0건인가
- 브로드캐스트 지연 p95 가 300ms 아래인가
- 공매도 집중이 발동했고 펌프 후 덤프가 실제로 왔는가
- 1위가 후반에 한 번도 안 바뀌지 않았는가
- 안정형 3종목의 거래량이 너무 적지 않은가

리허설 뒤에는 DB 를 지워 본 라운드와 섞이지 않게 한다.

```bash
rm -f festival.db rehearsal.db
```

### 본 라운드

1. `./run.sh` 로 서버를 띄운다.
2. 프로젝터에 `/board` 를 띄운다.
3. 관리자 화면 `/admin` 에서 로그인하고 시나리오를 고른다.
   **배속은 반드시 1로 둔다.** 배속은 리허설 전용이다.
4. 시작을 누른 뒤 참가자에게 QR 을 안내한다. 라운드 중에도 참가할 수 있다.
5. 30분 뒤 자동으로 끝난다. 중간에 멈춰야 하면 일시정지, 끝내려면 종료를 누른다.
6. 관리자 화면에서 CSV 를 내려받는다. `result.csv` 가 최종 순위다.

### 운영 중 생길 수 있는 일

| 상황 | 대처 |
|---|---|
| 참가자 휴대폰 화면이 멈춤 | 새로고침하면 기기 토큰으로 자동 복구된다. 보유와 현금은 그대로다 |
| 욕설 닉네임 | 관리자 화면에서 참가자 번호로 강제 퇴장 |
| 닉네임 중복 | 참가자 화면에서 바로 안내되므로 다시 입력하면 된다 |
| 누가 실수로 전량 매수 | 한 종목 총자산 50% 상한이 있어 전 재산이 한 종목에 들어가지는 않는다 |
| 서버가 죽음 | 다시 띄우면 보유와 현금은 DB 에서 복구되지만 실시간 위험조정 통계는 사라진다. 사후 재구성은 가능하다 |

## 다음 판, 다음 해

새 시나리오는 코드를 고치지 않고 `scenarios/` 에 `.json` 파일만 넣으면 된다.
관리자 화면이 폴더를 자동으로 읽고, 잘못된 파일은 이유와 함께 목록에 표시한다.

`scenarios/festival_01.json` 을 복사해 고치는 것이 가장 빠르다. 로더가 검사하는 것

- 구간에 빈틈이나 겹침이 없는지, `total_ticks` 에서 끝나는지
- `dampening_cap` 이 0 이상 1 미만인지 (1 이상이면 가격 방향이 뒤집힌다)
- 유동성이 0 이 아닌지, 이벤트가 라운드를 넘어가지 않는지
- 초반 90틱에 헤드라인이 없는지, 뉴스 간격이 90초~7분인지 (경고)
- 직접형 3개 이상, 간접형 2개 이상, 반례형 정확히 1개인지 (경고)

## 구조

```
backend/
  price_engine.py      틱당 가격 계산. 난수까지 주입받는 순수 함수
  index_engine.py      공포지수·환율 평균회귀와 목표값 램프 보간
  event_scheduler.py   뉴스와 공매도 2단계 스케줄 사전 전개
  scenario_loader.py   scenarios/*.json 스캔·검증·파싱
  game_loop.py         틱 진행, 주문 큐, 체결, 브로드캐스트
  ws_hub.py            WebSocket 연결 관리
  scoring.py           수익률, 위험조정점수, MDD, 3종 순위
  analysis.py          결과 분석 (tick_log, orders, events_fired 만 사용)
  simulate_tuning.py   서버 없이 엔진만 부르는 파라미터 그리드 서치
  self_check.py        자가 검증 8항목과 파라미터 자동 조정 루프
  bots.py              봇 5종. 튜닝과 자가 검증이 공유
  main.py              FastAPI 앱, API, 정적 서빙
frontend/src/pages/    화면 9개
scenarios/             시나리오 JSON
scripts/               리허설, 부하, E2E
docs/                  설계와 확인 지점 기록
```

## 체험판

서버 없이 브라우저만으로 도는 축약판이 `web-demo/` 에 있다. 엔진 계산과 시나리오는
같지만 혼자 봇 15명과 겨루는 형태라, 보여주기용이다. 행사에 쓰는 것은 위의 서버 버전이다.

시나리오를 고쳤으면 `./web-demo/build.sh` 를 다시 돌려야 체험판도 같이 바뀐다.

## 명령어 모음

```bash
./setup.sh                                  설치와 빌드
./run.sh                                    서버 실행
./run_all_tests.sh                          전체 테스트
./run_all_tests.sh --unit                   단위 테스트만
./scripts/run_rehearsal.sh 50               리허설
python3 scripts/load_test.py                부하 테스트 (WebSocket 50개)
python3 scripts/e2e_smoke.py                E2E 스모크
python3 -m backend.simulate_tuning          파라미터 그리드 서치
python3 -m backend.self_check               자가 검증 루프
```

## 라이선스와 출처

- 종목명, 기업 서사, 뉴스 헤드라인은 전부 가상이다. 실존 기업명, 로고, 상표를 쓰지 않는다.
- 시장 데이터는 전부 프로그램이 생성한다. 실제 주가, 환율, 지수 API 를 쓰지 않는다.
- 폰트는 Black Han Sans 와 Noto Sans KR 을 로컬에 번들링했다. 둘 다 SIL Open Font
  License 로 재배포할 수 있다.
