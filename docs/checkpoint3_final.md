## 2. 리허설 결과 (`./scripts/run_rehearsal.sh 50`)

봇 50명이 실제 서버에 HTTP 와 WebSocket 으로 붙어 375틱을 완주했다.
서버, DB, WebSocket, 체결 로직을 전부 통과시킨 결과다.

### 공매도 함정이 실제로 작동하는가

| 이벤트 | 펌프 실현 | 덤프 실현 | 순효과 | 펌프 진입 | 덤프 전 탈출 |
|---|---|---|---|---|---|
| EV05 | +16.6% | -15.7% | -1.7% | 11명 | 1명 (9%) |
| EV09 | +7.3% | -15.6% | -9.5% | 3명 | 0명 (0%) |

배지를 보고도 미끼를 문 봇이 거의 빠져나오지 못한다. 교육 효과로는 의도한 대로이지만
**현장에서 너무 가혹하게 느껴질 수 있다.** 덤프 구간을 늘려 완만하게 만들지 여부는
사람이 리허설 체감으로 판단해야 한다. 임의로 바꾸지 않았다.

### 반응 지연이 펌프 구간을 잡아먹는가

가장 짧은 펌프 구간이 6틱이고 주문은 다음 틱에 체결되므로, 반응 지연이 5틱을 넘으면
펌프 안에 진입할 수 없다. 스윕한 1틱과 4틱은 모두 한도 안이다.

지연 1틱에서 평균 9.3명, 4틱에서 8.3명이 진입했다. **처음 해 보는 사람 기준 1~4틱
지연으로도 펌프 구간에 반응할 시간이 충분하다.**

### 군집 확률 스윕에서 나온 것

| 군집 | 펌프 진입 | 주문 거부 |
|---|---|---|
| 0.0 | 23.0명 | 27건 |
| 0.4 | 2.0명 | 212건 |
| 0.8 | 1.5명 | 696건 |

군집이 높을수록 펌프 진입이 **줄어든다.** 봇이 군중 표적에 먼저 한 종목 50% 상한까지
채워서 정작 공매도 구간에 살 여력이 남지 않기 때문이다.

이건 버그가 아니라 50% 비중 제한의 정상 동작이다. 다만 현장에서 한 종목 쏠림이
심하면 같은 일이 벌어져 "사고 싶은데 못 산다"는 불만이 나올 수 있다.

리허설에서 거부 사유 1위가 비중 상한 초과(304건)로 나와서, **종목 상세 화면에
"최대 N주 (비중 상한 기준)" 안내를 추가**했다. 봇은 이 안내를 보지 않으므로
보고서의 거부 건수는 실제보다 부풀려져 있다.

## 3. 자가 검증 결과 (`python3 -m backend.self_check`)

시드 30개, 봇 40마리, 군집 0.5 로 돌려 8개 항목 전부 통과했다. 조정 없이 1회차에 통과.

| 항목 | 판정 | 내용 |
|---|---|---|
| (1) 종목 등락률 분포 | 통과 | 30회 모두 상승·하락이 섞임 |
| (2) 안정형 대조군 | 통과 | 안정형 0.342% 대 밈·비전형 0.963%, 2.8배 |
| (3) 지수 생동감 | 통과 | 최장 정체 공포 5틱, 환율 5틱 (기준 20틱) |
| (4) 지수 폭주 | 통과 | 공포 15.1~56.2, 환율 이탈 4.22% (기준 ±15%) |
| (5) 뉴스 간격 | 통과 | 8개 간격이 106~202초 |
| (6) 공매도 함정 | 통과 | 펌프 배율 1.065~1.158, 불변 조건 위반 0건 |
| (7) 승부 긴장감 | 통과 | 후반 1위 교체 평균 7.3회, 고정된 회차 1/30 |
| (8) 파산·무의미 | 통과 | -80% 밑 봇 0%, ±5% 안 45.6% |

### 조정 루프가 실제로 동작하는지 따로 확인했다

한 번에 통과하면 자동 조정이 도는지 알 수 없다. 그래서 지수 노이즈를 0.01 로,
종목별 노이즈를 전부 같게 만든 시나리오를 따로 만들어 돌렸다.

- 1회차: (2)와 (3) 실패를 잡아냄
- 조정: 임계치에서 필요한 noise_sigma 를 역산해 0.01 → 0.24 / 0.64, 안정형과
  밈형 노이즈를 측정된 배율에 맞춰 양쪽으로 벌림
- 2회차: 8개 항목 전부 통과

처음에는 고정 배율(1.35배)로 밀었는데 초기값이 크게 어긋나면 5회 안에 따라잡지
못했다. 측정값에서 필요한 값을 직접 역산하는 방식으로 바꿔서 1회 만에 수렴한다.

판정 기준도 하나 강화했다. (2)는 원래 "안정형 < 밈형" 이기만 하면 통과였는데,
1.3배 정도는 우연으로도 나와서 **1.5배 마진**을 요구하도록 바꿨다.

## 4. 잔여 위험

코드로 해결하지 못한 것들이다. 숨기지 않고 남긴다.

### 높음

**1. 학교 와이파이의 AP isolation**
단말 간 통신이 차단되어 있으면 휴대폰이 노트북에 접속할 수 없다. 코드로 해결 불가능하고,
행사 당일 가장 큰 단일 실패 요인이다.
→ 대비: 전날 휴대폰 한 대로 반드시 접속 확인. 안 되면 노트북 핫스팟. README 에 적어 뒀다.

**2. 실제 참가자 50명으로 검증한 적이 없다**
모든 수치는 봇 시뮬레이션과 봇 리허설 결과다. 사람은 봇과 다르게 움직인다.
특히 참가자 저항(`f`, `damp`)이 실제로 체감되는지는 사람으로 확인해야 한다.
→ 대비: 본 라운드 전에 사람 몇 명이라도 붙여 한 판 돌려 본다.

### 중간

**3. 참가자 저항이 얼마나 체감될지 불확실하다**
봇 기준 시장 영향 피크가 2.11% 다. "가격이 눈에 띄게 저항한다"고 하기엔 약하다.
실제 50명은 봇보다 심하게 몰리므로 더 클 것으로 보지만 **확인된 것이 아니다.**
→ 대비: `resistance_coef` 는 시나리오 JSON 파라미터라 현장에서 바로 바꿀 수 있다.

**4. 공매도 함정이 가혹할 수 있다**
펌프 구간에 들어간 봇의 덤프 전 탈출률이 0~9% 다.
→ 대비: 덤프 `ticks` 를 늘리면 완만해진다. 시나리오 파일만 고치면 된다.

**5. 서버 크래시 시 실시간 위험조정 통계 소실**
보유와 현금은 DB 에서 복구되지만, 메모리에만 있는 틱별 수익률 누적은 사라진다.
사후에 `tick_log` 와 `orders` 로 재구성할 수는 있다.
→ 대비: 라운드 중에는 노트북에서 다른 무거운 작업을 하지 않는다.

**6. 섹터 태그가 종목을 그대로 드러낸다**
스펙 6번의 7종목이 전부 다른 섹터라 태그를 보면 어느 종목인지 알 수 있다.
방향(호재·악재)을 감추는 부분은 그대로 지켜진다.
→ 종목 구성을 바꿔야 해결되는 문제라 손대지 않았다.

### 낮음

**7. 폰트 서브셋에 없는 글자**
닉네임에 한자나 드문 기호를 쓰면 깨질 수 있다. 닉네임 입력이 한글·영문·숫자만
받도록 막아 뒀다.

**8. 욕설 필터의 한계**
자체 단어 목록이라 우회가 가능하다.
→ 대비: 관리자 화면에서 참가자 번호로 즉시 강제 퇴장할 수 있다.

**9. 노트북 절전**
30분 동안 깨어 있어야 한다. README 운영 순서에 넣어 뒀다.

| 영향력 지표 | 전략 수익률 표준편차 | 봇 유무 반사실 비교 | 원래 지표는 저항 계수에 반응하지 않음 |
| 튜닝 봇 군집 | 없음(독립) | 그리드 축으로 추가 | 독립 봇만으로는 측정 대상이 나타나지 않음 |

`tick_seconds` 4.8초, `total_ticks` 375, 14번 디자인 값, 종목명과 서사는 바꾸지 않았다.

---

## 6. 확정하지 않은 것

- **`resistance_coef = 0.7`, `dampening_cap = 0.6` 은 리허설 전 기준값이다.**
  스펙 8번이 요구한 대로 최종 결정은 사람이 현장 체감으로 내려야 한다.
- 리허설과 자가 검증의 모든 수치는 봇 기준이다.
- 공매도 덤프 강도를 완화할지는 사람 판단 영역으로 남겨 뒀다.
